# Catatan implementasi Baileys

Sumber resmi diperiksa pada 7 November 2026. Paket yang terkunci di repo sumber dan versi registry saat pemeriksaan sama-sama `7.0.0-rc14`; paket memakai `pino ^9.6` dan berbasis ESM.

Dokumentasi pairing resmi: https://baileys.wiki/authentication/pairing-code. Nomor harus berupa digit saja termasuk kode negara (tanpa `+`, spasi, tanda kurung, atau tanda hubung). API yang dipakai adalah `requestPairingCode(number)`, dipanggil setelah event `connection.update` menyertakan `qr`, dan tidak diminta jika kredensial telah terdaftar. Panduan menyebut kode 8 digit, sedangkan implementasi lokal rc14 menghasilkan string pairing 8 karakter Crockford/alfanumerik; panel menampilkan nilai yang dikembalikan library tanpa mengubah formatnya. Hasil membuat kode belum membuktikan bahwa pengguna berhasil menautkan perangkat.

Dokumentasi pengelolaan sesi: https://baileys.wiki/authentication/session-management. `useMultiFileAuthState` menulis kredensial dan kunci Signal ke berkas, dan dokumentasi menyatakan helper ini bukan pilihan produksi. File auth memuat private key jangka panjang, sehingga harus dijaga seperti SSH key, tidak boleh di-commit atau diekspos. Produksi sebaiknya memakai auth-state store database yang durable dan terlindungi.

Migrasi v7: https://whiskey.so/migrate-latest. Baileys v7 memiliki perubahan breaking dan menggunakan ESM. Repo resmi: https://github.com/WhiskeySockets/Baileys. Proyek tersebut tidak berafiliasi dengan WhatsApp; pemakai bertanggung jawab mematuhi ketentuan layanan dan menghindari spam/penyalahgunaan. Informasi paket: https://www.npmjs.com/package/@whiskeysockets/baileys.

Issue resmi pairing yang menghasilkan kode tetapi gagal ditautkan (v7.0.0-rc13; ditutup setelah laporan perbaikan): https://github.com/WhiskeySockets/Baileys/issues/2590. Karena itu, tes saat ini hanya menyatakan request berhasil dan kode tampil, bukan bahwa WhatsApp selesai menautkan akun.

Untuk tes sementara, setiap user memakai direktori auth privat per user ID; kode hanya di memori dan tidak masuk log atau `store.json`; data uji dihapus ketika request kedaluwarsa. Sebelum produksi, ganti helper file-state dengan adapter auth durable yang aman.

## Status-event worker notes
- Dokumentasi event Baileys menjelaskan `messages.upsert` sebagai event pesan masuk, dengan `type: 'notify'` untuk pesan yang diterima saat socket online; `messages.update` membawa perubahan status pesan: https://baileys.wiki/concepts/events
- Pengiriman story/status `status@broadcast` dapat berbeda menurut versi Baileys/WhatsApp; issue berikut menunjukkan laporan yang berbeda antar versi, sehingga worker hanya mencatat event yang benar-benar dikirim Baileys dan tidak boleh mengklaim semua story pasti diterima: https://github.com/WhiskeySockets/Baileys/issues/2388
- Worker mencatat event story `notify`, `append`, dan `messaging-history.set` yang benar-benar diterima Baileys ke `DATA_AKUN/<username>/ReadSwReactionsw/swtrack/` sebelum memprosesnya. Batch history yang tiba sebelum worker mulai ditahan sebagai metadata status minimum sampai worker terpasang. Entri pending dipulihkan pada attach/reconnect sampai TTL 24 jam. Mode Read Only mengirim tanda dilihat tanpa emoji; mode Read Only + ReadSW mencoba reaksi tertunda hanya jika entri semula mengizinkan reaksi dan preferensi akun saat ini tetap mengaktifkannya. Pengiriman tanda dilihat yang sudah sukses tidak diulang saat hanya reaksi yang pending. Pemilik story dapat melihat tanda dilihat atau reaksi. Media dan isi status tidak disimpan. `ceksw/swstats.json` mencatat agregat per kontak dengan deduplikasi, sementara `users/` menyimpan metadata kontak ber-ID hash.

## Pembandingan dengan ReadSwEsm_V1
- Repo yang diperiksa: https://github.com/Wilykun/ReadSwEsm_V1. README mendokumentasikan `autoReadStory` dengan `autoReaction`, `randomDelay`, `delayMinMs: 1000`, dan `delayMaxMs: 20000`.
- `SEMUA_FITUR/readsw/readsw.js` membedakan Read Only (`autoReaction: false`) dengan Read + Reaksi (`autoReaction: true`) serta menyediakan rentang delay acak.
- `src/helper/jadibotSettings.js` menyimpan preferensi per nomor Jadibot; `src/helper/jadibot.js` menandai status dibaca dengan receipt `read` dan mengirim reaksi melalui `status@broadcast` plus `statusJidList`.
- `src/helper/swtrack.js` pada `logStoryView()` menyusun bidang Mode, TipeStory, IdStory, Selamat, Hari, Tanggal, Waktu, Nama, Nomor, TotalStory, EmojiMode, Berhasil, Reaksi, Resolve, dan Delay; panggilan dari `src/helper/jadibot.js` memasok data tanggal, pengirim yang dimasking, jumlah story harian, hasil receipt/reaksi, dan delay. Sumber: [logger](https://github.com/Wilykun/ReadSwEsm_V1/blob/main/src/helper/swtrack.js#L606-L659) dan [pemanggil Jadibot](https://github.com/Wilykun/ReadSwEsm_V1/blob/main/src/helper/jadibot.js#L1571-L1604).
- Bagian yang ditinjau untuk backlog adalah [helper swtrack di branch ReadSwEsm_V7](https://github.com/Wilykun/ReadSwEsm_V1/blob/ReadSwEsm_V7/src/helper/swtrack.js), [selector pending](https://github.com/Wilykun/ReadSwEsm_V1/blob/ReadSwEsm_V7/src/helper/swtrack-pending.js), [worker Jadibot](https://github.com/Wilykun/ReadSwEsm_V1/blob/ReadSwEsm_V7/src/helper/jadibot.js), dan [entry point utama](https://github.com/Wilykun/ReadSwEsm_V1/blob/ReadSwEsm_V7/index.js). Kode sumber memakai `ceksw/swstats.json` untuk statistik/deduplikasi, `swtrack/` untuk file status per kontak, dan memiliki migrasi format `users` lama ke tracking per kontak. Mode Read Only menyelesaikan entry setelah dibaca; mode Read+Reaction dapat retry reaksi yang belum berhasil.
- Entry point sumber mengaktifkan `syncFullHistory: true` dan menyaring `messaging-history.set` untuk status. Proyek ini mengaktifkannya pada socket pairing baru dan reconnect; listener hanya menyimpan status terpilih ke backlog. Dokumentasi Baileys menjelaskan history datang dalam batch `messaging-history.set`, dapat mencakup chat/kontak/pesan, serta full sync dapat menambah waktu startup dan memori. Dokumen resmi merekomendasikan preset macOS Desktop untuk cakupan full history yang lebih besar, sehingga preset tersebut kini dipakai pada socket pairing/reconnect selanjutnya. Sebelumnya perubahan preset pada sesi tertaut diikuti reconnect berulang dengan kode 428 (`DisconnectReason.connectionClosed`); akun kemudian menghapus sesi lokal, jadi koneksi berikutnya akan memakai preset macOS sejak pairing. Sumber: [Baileys history sync](https://baileys.wiki/advanced/history-sync) dan [Baileys events](https://baileys.wiki/concepts/events).
- Adaptasi lokal menyimpan semua data di `DATA_AKUN/<username>/ReadSwReactionsw/`, tidak di folder auth `session.json`. `swtrack/` menampung pending event privat, `ceksw/` menghitung agregat per akun, dan `users/` berisi metadata kontak yang hanya dikunci dengan hash. TTL lokal 24 jam agar entry tidak diretry setelah masa status normal berakhir.
- Panel ini menyimpan pengaturan dalam profil bot per `userId` akun yang masuk, bukan memakai nomor WhatsApp sebagai kunci. Delay dibatasi 1–20 detik; rentang acak mencakup nilai minimum dan maksimum. Reaksi hanya diproses pada mode Read Only + ReadSW ketika toggle reaksi aktif dan set emoji tidak kosong.
